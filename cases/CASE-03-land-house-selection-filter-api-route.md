## Ошибка 422 при открытии подбора ИЖС из-за неверного API-роута

**Проект:** Флэт, CRM.  
**Модуль:** заявки на ИЖС, параметры подбора объектов.  
**Дата проверки:** 23.11.2026.  
**Окружение:** beta · Яндекс Браузер · DevTools (Network).

### Ситуация

Проверяла доработку параметров подбора для заявок на индивидуальное жилищное строительство (ИЖС): перенос площади участка из анкеты и отдельное сохранение параметров.

При переходе во вкладку «Подбор» внутри карточки заявки возникала ошибка 422 с сообщением «Фильтр подбора не соответствует типу заявки». Текущие параметры подбора в карточке не отображались.

### Ход проверки и рассуждений

1. Открыла существующую заявку ИЖС и воспроизвела ошибку во вкладке «Подбор».
2. В DevTools → Network обнаружила запрос `GET /api/v1/deal/buy-nb/selection-filter/{dealId}` с ответом `422 Unprocessable Content`.
3. Создала новую заявку ИЖС и повторила проверку. Ошибка воспроизвелась, поэтому проблема не ограничивалась ранее созданными заявками.
4. Проверила ответ API карточки заявки: `subtype.value: contract`. Сервер передавал подтип ИЖС.
5. Открыла отдельную страницу подбора той же заявки. Там использовался запрос `GET /api/v1/deal/buy-nb/selection-filter/land-house/{dealId}`, который возвращал `200 OK`. Страница открывалась, а значение площади участка из анкеты отображалось в фильтре.
6. Сопоставила запросы двух интерфейсов и передала разработчикам различие в выборе API-роута. Бэкенд-разработчик подтвердил причину ошибки.

### Найденная проблема

При открытии вкладки «Подбор» в карточке заявки ИЖС фронтенд обращался к роуту для новостроек:

`GET /api/v1/deal/buy-nb/selection-filter/{dealId}`

Для заявок ИЖС с `subtype.value: contract` требовался отдельный роут:

`GET /api/v1/deal/buy-nb/selection-filter/land-house/{dealId}`

Из-за выбора неподходящего эндпоинта сервер возвращал 422. При этом отдельная страница подбора уже использовала корректный роут и загружалась успешно.

### Риски для продукта

- Пользователь не видит текущие параметры подбора внутри карточки заявки.
- Ошибка мешает проверить настройки, с которыми ведётся подбор объектов.
- Разное поведение карточки заявки и отдельной страницы подбора создаёт путаницу.
- Доработка параметров ИЖС остаётся неполноценной, пока один из интерфейсов использует неподходящий API.

### Мой вклад

Проверила воспроизводимость на существующей и новой заявках, сопоставила коды ответов и эндпоинты, проверила передаваемый подтип заявки и сравнила поведение двух интерфейсов.

Локализовала дефект до выбора API-роута на фронтенде и передала разработчикам конкретные запросы, условия воспроизведения и ожидаемое поведение.

### Результат

Причина ошибки установлена и подтверждена бэкенд-разработчиком. Дефект передан для исправления на фронтенде. На момент описания кейса успешный ретест исправления не зафиксирован.

- Проверку бизнес-логики с учётом подтипа заявки.

- Локализацию дефекта на границе фронтенда и API.
- Проверку воспроизводимости и взаимодействие с разработчиками.

## PDF не принимается при распознавании паспорта в CRM

**Проект:** Флэт, CRM.  
**Модуль:** Контур (CV), диалог "Проверить физ. лицо".  
**Дата проверки:** 30.10.2025.  
**Окружение:** test · v.689ce285 · admin · Windows 11 / Chrome / 1920×1080.

### Ситуация

В модуле распознавания паспорта пользователь загружает первую страницу документа, чтобы перенести распознанные данные в форму.

По бизнес-ожиданию загрузка должна была работать согласованно с разделом "Документы клиента", где PDF принимается. Нужно было проверить поведение диалога при загрузке одностраничного PDF и обратную связь для пользователя.

### Ход проверки и рассуждений

1. Открыла диалог "Проверить физ. лицо".
2. Выбрала одностраничный PDF с первой страницей паспорта.
3. Проверила реакцию интерфейса и запуск распознавания.
4. Зафиксировала стабильное воспроизведение: файл не загружался, распознавание не запускалось.
5. Сформулировала вопрос к требованиям: модуль должен поддерживать PDF или явно отклонять его с объяснением?

### Найденная проблема

Загрузка PDF игнорировалась. Распознавание не запускалось, при этом пользователь не получал понятного объяснения причины.

Поддержка PDF требовала подтверждения требований. Независимо от принятого решения интерфейс должен был сообщать результат попытки загрузки.

### Риски для продукта

- Пользователь не понимает, что мешает загрузке, и повторяет попытки.
- Разные правила загрузки в разделах CRM затрудняют работу с документами.
- Сценарий заполнения данных через распознавание прерывается.
- Возникают дополнительные обращения в поддержку.

### Мой вклад

Описала воспроизводимый сценарий и привязала его к бизнес-ожиданию согласованного поведения модулей.

Предложила два варианта решения для согласования:

- Поддержать PDF и запускать распознавание.
- При отсутствии поддержки явно отклонять PDF с понятным сообщением.

Также подготовила критерии повторной проверки: выбранное поведение соответствует требованиям, пользователь получает обратную связь, диалог остаётся работоспособным и в консоли нет JS-ошибок.

### Результат

Оформлен дефект с описанием поведения, вопросом к требованиям и проверяемыми критериями приёмки. Команда получила основу для выбора решения и последующего ретеста.
